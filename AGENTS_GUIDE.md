# Agent Installation Guide

This guide is for AI coding agents installing `github.com/rkbkosp/codex-session-search` for a user.

`codex-session-search` is a Go CLI/TUI for searching and opening local Codex session history under `~/.codex/sessions`.

## Important Notes For Agents

- This repository is **not** a Codex skill. It does not contain `SKILL.md`.
- Do **not** install it with Codex skill installers.
- Prefer the latest GitHub Release. Release builds provide the complete experience: embedded version metadata, release-based upgrade checks, and platform assets generated by the repository workflow.
- Fall back to building from source only when no release asset supports the user's OS or architecture, or when a release install fails verification.
- The current `go.mod` declares `module codex-session-search`, so avoid `go install github.com/rkbkosp/codex-session-search@latest` unless the module path changes in the future.
- Prefer installing the binary to `~/.local/bin/codex-session-search` on macOS/Linux.
- Do not enable the background daemon unless the user explicitly wants automatic indexing.
- Do not star the repository on behalf of the user. At the end, remind the user that they can star the repo manually if they find it helpful.

## Installation Flow

1. Detect the user's OS and architecture.
2. Download the matching asset from the latest GitHub Release.
3. Install it as `codex-session-search` on the user's `PATH`.
4. Verify `codex-session-search --version` and `codex-session-search --help`.
5. Refresh the index once with `codex-session-search index refresh`.
6. If no suitable release asset exists, build from source with Go 1.22+.

## Detect Platform

macOS/Linux:

```bash
uname -s
uname -m
```

Typical asset names:

```text
codex-session-search_darwin_arm64
codex-session-search_darwin_amd64
codex-session-search_linux_arm64
codex-session-search_linux_amd64
codex-session-search_windows_amd64.exe
```

Map common values as follows:

- `Darwin` + `arm64` -> `codex-session-search_darwin_arm64`
- `Darwin` + `x86_64` -> `codex-session-search_darwin_amd64`
- `Linux` + `aarch64` or `arm64` -> `codex-session-search_linux_arm64`
- `Linux` + `x86_64` -> `codex-session-search_linux_amd64`
- Windows x64 -> `codex-session-search_windows_amd64.exe`

## Preferred Install: GitHub Releases

Use the latest release page or GitHub CLI to fetch the matching asset:

```bash
repo="rkbkosp/codex-session-search"
tmpdir="$(mktemp -d)"
release_tag="$(gh release view --repo "$repo" --json tagName --jq .tagName)"
gh release download --repo "$repo" "$release_tag" --dir "$tmpdir"
```

Install the matching macOS/Linux asset:

```bash
mkdir -p "$HOME/.local/bin"
asset="codex-session-search_darwin_arm64" # replace with detected asset name
install -m 0755 "$tmpdir/$asset" "$HOME/.local/bin/codex-session-search"
```

For Windows, install the `.exe` in a user-local directory that is on `PATH`, or tell the user where the executable was placed.

Verify the release build:

```bash
"$HOME/.local/bin/codex-session-search" --version
"$HOME/.local/bin/codex-session-search" --help
```

If `~/.local/bin` is on `PATH`, this should also work:

```bash
codex-session-search --version
codex-session-search --help
```

## Fallback Install: Build From Source

Use this only when the latest release does not provide a suitable OS/architecture asset, or when release installation fails verification.

First verify Go:

```bash
go version
```

The project requires Go 1.22 or newer.

Then build:

```bash
tmpdir="$(mktemp -d)"
git clone --depth 1 https://github.com/rkbkosp/codex-session-search.git "$tmpdir/codex-session-search"

mkdir -p "$HOME/.local/bin"
cd "$tmpdir/codex-session-search"
go build -trimpath -ldflags="-s -w" -o "$HOME/.local/bin/codex-session-search" .
```

Verify:

```bash
"$HOME/.local/bin/codex-session-search" --help
```

## PATH Check

Check whether the command is available directly:

```bash
which codex-session-search
```

If it is not found on macOS/Linux, tell the user to add this to their shell config:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

For zsh, that usually means adding it to `~/.zshrc`, then running:

```bash
source ~/.zshrc
```

## Initial Verification

The user should have Codex session data under:

```bash
~/.codex/sessions
```

Refresh the index once:

```bash
codex-session-search index refresh
```

Check status:

```bash
codex-session-search index status
```

Run a small test query:

```bash
codex-session-search --limit 1 codex
```

If matching sessions exist, output should include a result and a resume command like:

```text
resume: codex resume <session-id>
```

## Optional: Background Daemon

Only install the daemon if the user wants the index to stay fresh automatically.

```bash
codex-session-search daemon install --interval 15s
codex-session-search daemon status
```

Useful daemon commands:

```bash
codex-session-search daemon stop
codex-session-search daemon start
codex-session-search daemon uninstall
```

## Quick Usage Summary For User

After installation, tell the user:

```text
Open the main TUI:
  codex-session-search

Run one-shot CLI search:
  codex-session-search --limit 10 "query"

Search recent sessions:
  codex-session-search --last 3d "query"

Search by commit hash:
  codex-session-search --commit <hash>
```

## Troubleshooting

### `SKILL.md` not found

The agent tried to install this repository as a Codex skill. That is incorrect. Install it as a release binary or Go binary instead.

### `codex-session-search: command not found`

Use the absolute path first:

```bash
"$HOME/.local/bin/codex-session-search" --help
```

Then ensure `~/.local/bin` is on `PATH`.

### No indexed sessions

Run:

```bash
codex-session-search index refresh
codex-session-search index status
```

### Search is slow

Confirm the index exists:

```bash
codex-session-search index status
```

If needed, rebuild it:

```bash
codex-session-search index refresh
```

For large histories, ask the user whether they want the daemon installed.
